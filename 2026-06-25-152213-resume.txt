============================================================
已确认的设计决策汇总
============================================================

1. 接口策略：扩展现有文生图接口，支持可选参考图（subject_reference）
2. 参考图来源：双通道（本地上传 + 历史图片选择），统一收敛为 referenceResourceId
3. 触发入口：/image 命令和非 /image 普通消息都支持
4. 意图判断：LLM 工具调用自然决定，不在 runChatStream 写死
5. 工具入参：显式加 referenceResourceId（可选），LLM 从增强消息获取
6. 参考图传入：Base64 Data URL（data:image/jpeg;base64,...）
7. 资源查询：复用现有 ChatMessageResourceMapper.selectByResourceId
8. 上传端点：新增 POST /api/chat/resources/upload（multipart）
9. 用户消息展示：参考图在用户消息气泡中展示（resource_kind=REFERENCE）
10. 参考图数量：先支持 1 张

============================================================
后端改动清单（10处）
============================================================

1. MiniMaxImageGenerationRequest — 加 SubjectReference(type, imageFile)，可为 null
2. MiniMaxHttpImageClient.generate — Map.of → HashMap，按需塞 subject_reference
3. ImageGenerationServiceImpl — sourceResourceId 非空时：selectByResourceId 查 storageKey → open 读字节 → Base64 Data URL → 构造 SubjectReference
4. ImageGenerationTool — generateImage(memoryId, prompt, referenceResourceId)，描述更新，填入 ImageSubAgentCommand.sourceResourceId
5. ChatAgentExecutionCommand — 加 referenceResourceId 字段
6. ChatService.streamChat + ChatController — 透传 referenceResourceId
7. ChatServiceImpl — streamChat/runChatStream/emitImageCommandEvents 透传，后者填 sourceResourceId
8. HAssistantStreamingExecutor + AgenticSyncExecutor — 消息增强（refId 非空时给 LLM 的消息追加参考图 ID 提示）
9. ChatMessageRequest — 加 referenceResourceId
10. 新增 POST /api/chat/resources/upload（multipart）→ ResourceStorage.save + 写 chat_message_resources 记录 → 返回 {resourceId, viewUrl}

============================================================
前端改动清单（5处）
============================================================

1. 输入框加图片按钮 + 已选参考图缩略条（可移除）
2. ImageMessageContent 加"用作参考图"按钮
3. buildChatSendPayload 加 referenceResourceId
4. handleSubmit 带上 referenceResourceId，发送后清空
5. 新增 uploadChatResource 调用 /api/chat/resources/upload
