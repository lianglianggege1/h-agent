# 2026-08-08

## 项目：声网 Conversational AI 语音 Agent
- 用户在研究声网对话式 AI 引擎（`/join` 接口、MCP 集成），目标是做一个"文字进 / 语音出"的语音 Agent。
- 关键约束：**用户没有公网环境**（无法提供公网 HTTPS 让声网云回调）。
- 用户意图：想在自己服务端跑 LLM（"自己服务(LLM 产文字)"），再接 TTS 转语音、发回 RTC 频道。
- 已澄清的架构结论：
  - 声网托管 `/join` 流程里 ASR→LLM→TTS 是声网云编排的，要调"你自己的 LLM/MCP"就必须公网可达 → 用户不满足。
  - 可行路径（无需公网）：**自编排桥接**——自己服务端进 RTC 频道（出站连 Agora）、收音频/文本、本地跑 LLM、WebSocket/HTTP 出站连 TTS 厂商拿音频、再 publish 回 RTC 频道。所有连接均出站。
  - LLM 本身只产**文字**，TTS 才产**语音**；用户听到的是 TTS 的活儿。
  - 参考项目：声网官方 `AgoraIO/openai-realtime-python`（服务端进 RTC + 用 WebSocket 连 OpenAI Realtime，自带 LLM+TTS 编排）。用户场景可把 OpenAI Realtime 换成"本地 LLM + 独立 TTS"两步。
  - 自编排需自己实现：VAD/静音检测、打断(barge-in)、话轮管理（托管流程免费送你）。

## 关键结论（已查声网官方文档确认 2026-08-08）
- 声网托管引擎要"自定义大脑"只有一条路：`llm.url` 指向自定义 OpenAI 兼容 HTTP 服务（SSE 流式）。官方博客明确：该 URL 必须是声网云能访问的**公网 HTTPS**，localhost/私网 IP 不行；请求是从声网云发出的。
- **没有 WebSocket / 推送式接入大脑的选项**。自定义 TTS（generic_http）也明确只支持 HTTP/HTTPS，拒绝 ws://；MCP endpoint 同理需公网。声网的 ASR/打断/TTS 与 LLM 回调是绑在同一条编排管线里的，拆不开。
- 因此"声网托管 ASR+打断+TTS + 保留 h-agent 自有 agent 逻辑"= 必须给大脑一个公网可达 URL。
- 但"公网可达"≠"要有公网 IP/开入站端口"。解锁方式（全是你侧出站）：
  ① 内网穿透隧道 cloudflared/frp/ngrok——出站建隧道拿公网 URL，防火墙不开入站端口；
  ② 薄公网中继——腾讯云 API 网关/云函数只暴露 `/v3/chat/completions` + api_key 鉴权，转发到内网 h-agent（企业更易接受、可审计）。
- 若连一个公网 URL 都不允许 → 只能自编排桥接，声网仅当传声管道，"打断"需自实现（VAD）。

## 环境确认与最终选型
- 用户环境 = **能联网的办公本**（有出网、无公网 IP、开不了入站端口）→ 属于"内网穿透可解"的情况。
- 选型：**cloudflared 或 ngrok**（它们自己提供公网入口，你只在办公本跑一个出站 agent 即可拿到公网 URL）。**frp 不适用**（frp 需要你自己有一台公网服务器跑 frps，用户没有）。
- 方案：h-agent 在本地暴露 OpenAI 兼容 + SSE 流式的 `/v3/chat/completions`（h-agent 现有 `LangGraphController.chatCompletions`/`executeStreaming` 基本就是这个形态），用 cloudflared 隧道暴露成公网 URL，Agora `llm.url` 指过去 → 白嫖声网托管 ASR+打断+TTS，agent 逻辑原样。
- 注意：Agora 请求会附带 turn_id/timestamp 等额外字段，转发前可剥离；端点要支持 SSE(stream:true)；加 api_key；cloudflared quick tunnel 的 URL 每次变（POC 够用，生产用命名隧道/中继）。

## 用户最终架构决断（2026-08-08）
- 用户明确：大脑必须是**客户自己的 agent 服务（h-agent）**，因为裸 LLM 读不了自有知识库；只有自己的 agent 才有 RAG/工具/知识库扩展能力。
- 关键澄清（已确认）：声网"自定义 LLM"的 `llm.url` 接的不是某个 LLM，而是"任何 OpenAI 兼容 + SSE 的服务"——即客户自己的 agent。声网只做 ASR+打断+TTS（声音），对大脑内部（RAG/工具/知识库）无感知不限制。
- **不使用声网的 mcp_servers**（那是给"没有自己 agent、想让声网给裸 LLM 接工具"的场景）；RAG/工具全在 h-agent 内部完成，只回最终文本。
- 最终架构：声网托管 ASR+打断+TTS；llm.url → cloudflared 隧道 → 本地 h-agent(orchestrator+RAG+知识库+工具)。

## 更优方案建议（2026-08-08）
- 点破：声网/TRTC 托管引擎是为"接托管大模型的语音 bot"设计的，大脑只能公网回调，与用户"大脑自己写"的场景天然冲突。
- 两个干净方案：
  - 方案A = 声网托管 + 公网中继（生产用云函数/API网关固定暴露 /v3/chat/completions，别用办公本隧道）。最快、改动最小、白嫖声网打断。
  - 方案B = **语音 Agent 框架 LiveKit Agents / Pipecat**：agent 逻辑跑在 worker 进程内，框架管 RTC 传输+VAD+打断，worker 出站连云端，零公网入口；ASR/TTS 自由接。更贴合"大脑自己写+零公网"。用户文档第四章本就推荐 LiveKit+LiveKit Agents。
- 建议路径：先用方案A办公本隧道快速 POC 验证体验；若"自主控大脑+零公网"是长期硬需求，转方案B。

## LiveKit 竞品格局（2026-07 GitHub 数据）
- 开源语音 agent 框架三巨头：**Pipecat**(Daily,13.4k星,Python,BSD,集成最广40+,transport可换Daily/LiveKit/WebSocket)、**LiveKit Agents**(11.4k星,Python+Node,Apache,可自托管媒体服务器+原生SIP电话+MCP工具)、**TEN Framework**(10.9k星,**声网Agora的开源框架**,C++核+Go/Python/JS绑定,图编排/多模态/数字人,延迟最低,传输走Agora RTC)。
- 其他：FastRTC(原型/demo)、Vocode(老,维护弱)、Bolna(快速电话agent)。
- 托管平台(不同类别,买成品)：Vapi/Retell/Bland/ElevenLabs/Agora ConvoAI。
- 关键洞察：**TEN Framework 是声网自家的开源框架**——想留在声网生态又要自己控大脑/免公网回调，TEN 是中间路线（agent 进程自己跑、出站连 Agora RTC）。
- MiniMax 能力核实：只有 TTS（WebSocket 流式,推荐 speech-2.6-turbo 低延迟），**无 STT/ASR 产品**；STT 需另配 FunASR/SenseVoice(本地)或阿里/腾讯/Deepgram(云端)。
- 成本结论：VAD/判停/打断算力≈0、不占成本；真正成本是 LLM/STT/TTS/RTC传输。自主可控✅，省成本有条件（量大才划算，且要GPU）。
- 附：声网托管引擎还支持 `chat.completion.custom_metadata` 首包，可在 LLM 响应里控制"是否可被打断 interruptable"和实时改 TTS 参数（自定义 LLM 场景适用）。
