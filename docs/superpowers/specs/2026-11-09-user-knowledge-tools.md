# 用户级主动知识库

日期：2026-11-09。产品设计已通过 grilling 确认，按本说明实现。

## 目标

知识库只归属于用户，与 Prompt、Agent 或 Session 无关。Agent 根据任务自主查询和沉淀可复用知识，不在每轮请求开始时自动查询，不在后台自动提取对话。

本期覆盖 HAssistant、普通 Harness 及具备工具权限的协作者。领域 Agent 与电话专用知识能力保持原有接入；Harness 的原生 MEMORY.md、每日流水和会话日志继续保留，Mem0 继续作为独立记忆能力。

## 数据与管理

- 去掉知识文档的 prompt_id 和向量中的 promptId；保留既有文档 ID、用户归属、全部向量及分块序号，不重新嵌入、自动合并同名文件或排除已删除 Prompt 下的文档。
- 上传、手工录入、列表、前端 API 和管理页面只依赖认证用户。旧带 promptId 的页面链接进入同一个用户知识库。
- 来源类型区分 FILE、MANUAL、AGENT。Agent 只能更新当前用户下 AGENT 来源的知识，不能改写 FILE / MANUAL，没有模型删除工具。用户仍可通过原管理入口删除自己的文档。
- Agent 知识保存完整正文、适用条件、版本、作者与来源引用。Agent 身份、会话和执行 ID 只用于追溯，不形成知识库分桶或限制同用户其他 Agent 的维护权限。

## 工具

两种框架使用同一应用模块、同一套 knowledge_* 工具：

| 工具 | 行为 |
| --- | --- |
| knowledge_list | 只读、分页浏览文档元数据，不创建默认 Prompt，不加载系统提示正文 |
| knowledge_search | 使用当前模型提交的查询直接检索，可限定文档；没有内部 LLM 扩写、路由 |
| knowledge_read | 按需展开命中周围的分块或指定版本，按字符与条数限制输出 |
| knowledge_save | 模型将标题、正文、适用条件与可用来源整理定稿后主动保存 |
| knowledge_update | 使用 expectedVersion 修订同用户的 Agent 知识，保留旧版本 |
| knowledge_history | 显式读取修订元数据和来源，旧版本内容通过 knowledge_read 展开 |
| knowledge_operation | 检查已提交但结果不明的操作，不重新创建知识 |

目录也只有模型调用后才读取。工具声明和用途说明常驻，知识正文不自动注入。来源信息始终随结果提供，模型自主决定是否在回答中展示引用。

工具身份取自可信执行上下文，不接受模型填写 userId。查询、目录、按 ID 读取、历史、写入和来源引用均校验用户归属。协作者只有在能力声明与平台权限允许时取得工具；Explore 模式只允许读取。

## 索引与读取

复用本地 embedding 模型和 PgVector，不引入额外的生成模型。上传、手工录入与 Agent 文本共用切片和索引逻辑。

每个新版本写入带 revision 的片段，片段 ID 根据文档、版本、序号稳定生成。旧数据缺少 revision 时视为版本 1。检索候选必须再次核实文档存在、用户归属、COMPLETED 状态和当前版本；孤立、未就绪及历史版本向量不进入默认搜索。

正常分块按 metadata.index 排序；缺失或非法序号使用稳定分页顺序并标记原顺序不可用。片段引用不冒充原始文件页码。现有上传文件二进制未保存，本期不提供原始文件下载或可靠 PDF 页码。

历史读取使用对应版本的标题、适用条件和来源，不用当前版本的信息覆盖旧版本。来源引用可链接到知识片段或已持久化的会话消息；引用只是 provenance，不把模型总结标成已经被用户确认的事实。

## 写入与失败

1. 先记录工具操作、完整稿件、切片参数、目标版本及来源，预留文档更新位置。
2. 以短事务领取操作租约，在数据库事务外计算 embedding 并 upsert 稳定 ID 的索引。
3. 确认当前租约和预留版本，在同一本地事务内发布正文、版本、修订历史和成功结果。

只有正文和索引完成才报告 OK。并发重复调用重放同一结果；版本冲突返回 CONFLICT，模型可重新读取后决定。索引故障返回 PENDING 和 operationRef，后台仅重试已经由模型发起的操作，不自行判断要新增哪些知识。重试遵循原稿、目标版本和切片参数；旧版本在新版本发布前仍可读取，部分新索引不会变成当前答案。

明确区分没有匹配结果、NOT_READY、NOT_FOUND、权限限制、CONFLICT、UNAVAILABLE 与 PENDING。模型根据任务决定继续通用回答、补查或追问，不编造来源。

## 与记忆的分工

知识库保存可复用资料、方法、操作步骤与解决问题的经验。Mem0 保存用户背景、偏好、协作约定及历史关键事实。不强制双写，不将原生 Harness 流水或 Mem0 自动复制到知识库。

## 现有数据注意点

原重解析接口会先删除文档和向量，却无法重读未保存的原文件。本次改为明确拒绝并保留现有数据，避免用户误操作造成知识丢失；不声称已补齐原文件重解析。
