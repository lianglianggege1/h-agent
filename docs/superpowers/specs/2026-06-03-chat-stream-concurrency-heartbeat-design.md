# 聊天流式心跳与并发闸门 — 设计规格

- 日期：2026-06-03
- 范围：仅后端聊天流式链路
- 目标：解决 agent 前置阻塞导致 SSE 心跳无法及时报活的问题，并为多用户、多智能体、多会话场景增加高并发保护

## 1. 目标与边界

本次仅解决两个问题：

1. `RAG / 路由 / 模型调用` 阻塞时，SSE 连接仍能持续发 heartbeat
2. 多用户高并发下，agent 执行不能无限放大，必须有限流闸门

已确认约束：

- 前端断开后，后端 agent **继续执行**
- 结果仍使用现有 `chat_session_messages` 与 `agent_run` 结构落库
- 超限时 **立即拒绝**，不排队
- 同一 `sessionId` 同时只允许 **1** 个运行中的 agent

本次不做：

- 队列化执行
- 前端重连续流
- 新任务系统
- 消息表结构调整

## 2. 现状问题

当前 `/api/chat/messages/stream` 返回 `Flux + SSE`，但 agent 主流程中存在阻塞步骤：

- 会话校验
- RAG 查询路由
- 知识检索
- 模型调用
- 工具调用

如果这些步骤在流开始阶段阻塞过久，heartbeat 不能及时发出，前端会误判连接失活。

## 3. 推荐方案

采用：**虚拟线程执行 agent + 独立 heartbeat + 三层并发闸门**

### 3.1 执行模型

- SSE 连接建立后，heartbeat 立即开始
- agent 主流程不在当前订阅线程直接执行
- agent 主流程提交到 `virtual thread per task executor` 中运行

这样即使 agent 被外部调用阻塞，也不会卡住 heartbeat。

### 3.2 心跳语义

- heartbeat 属于**传输层保活**
- heartbeat 不代表 agent 成功，只代表 SSE 连接当前仍可写
- heartbeat 与 agent 事件共用同一条 SSE 输出通道

### 3.3 agent 事件语义

在 SSE 连接仍然可用时：

- 增量内容继续发送 `chunk`
- agent 结束发送 `done`
- agent 失败发送 `error`

如果前端连接中途断开：

- 当前客户端不再收到后续事件
- 但 agent **继续执行**
- 最终结果仍按现有结构落库

## 4. 并发闸门

为防止高并发场景下虚拟线程把下游资源打满，增加三层闸门：

### 4.1 会话级闸门

- 维度：`sessionId`
- 规则：同一 `sessionId` 同时最多 1 个运行中的 agent
- 超限处理：立即拒绝，提示“当前会话正在处理中”

### 4.2 用户级闸门

- 维度：`userId`
- 规则：同一用户同时最多 `N` 个运行中的 agent
- 默认建议：`2~4`
- 超限处理：立即拒绝，提示“当前系统繁忙，请稍后再试”

### 4.3 全局级闸门

- 维度：全服务实例
- 规则：系统同时最多 `M` 个运行中的 agent
- 默认建议：先使用保守值，例如 `100`
- 超限处理：立即拒绝，提示“当前系统繁忙，请稍后再试”

## 5. 生命周期

### 5.1 请求进入

1. 建立 SSE 输出
2. 启动 heartbeat
3. 尝试获取会话级、用户级、全局级闸门
4. 任一闸门失败，立即返回错误并结束本次流式响应
5. 全部成功后，在虚拟线程中启动 agent

### 5.2 agent 完成

- 正常完成：写 assistant message，完成 `agent_run`
- 失败：写失败状态，结束 `agent_run`
- 无论成功失败，都必须释放三层闸门

### 5.3 前端断开

- 停止当前 SSE 的实时推送
- 不取消 agent 执行
- agent 正常收口并落库
- 收口完成后释放三层闸门

## 6. 错误感知

分两种情况：

1. **连接仍然存在**
   - agent 虚拟线程中的错误通过 SSE `error` 事件实时返回前端

2. **连接已经断开**
   - 当前前端无法实时感知
   - 错误通过现有 `agent_run` 与消息落库在后续查询中体现

这不是缺陷，而是“前端断开后 agent 继续执行”这一约束下的自然结果。

## 7. 实现范围

预计只需在现有聊天流式链路上做局部调整：

- `ChatServiceImpl.streamChat()`：改为虚拟线程执行 agent
- 聊天流式并发控制：新增三层闸门
- SSE heartbeat：确保不被 agent 前置阻塞影响

控制器路径、消息表结构、agent run 结构保持不变。

## 8. 推荐默认值

| 维度 | 默认值 |
|------|--------|
| 同会话并发 | 1 |
| 同用户并发 | 2~4 |
| 全局并发 | 100 |
| 超限策略 | 立即拒绝 |

## 9. 验证重点

实现后重点验证：

1. agent 启动前阻塞 30~60 秒时，heartbeat 仍持续输出
2. 同一 `sessionId` 并发发送第二条消息时立即拒绝
3. 单用户超过用户级上限时立即拒绝
4. 全局并发打满时立即拒绝
5. 前端断开后，agent 仍能继续执行并正确落库
