# MiniMax Video V2 升级说明

## 行为与兼容

普通助手和 Harness 均提供生成、查询、列表、取消/删除、H3 Context IR、2K 再生成能力。旧 V1 任务继续走原查询和下载接口，不会重新提交生成。

- 默认模型 `MiniMax-H3`，时长 6 秒，分辨率 768P；用户明确指定的模型、时长、分辨率优先，不自动降级。
- H3 支持 768P/2K，Highspeed 支持 768P，Lite/Max 支持 480P/768P。时长 4–15 秒，Max 最短 5 秒。
- 文生默认 16:9；首尾帧按接口规则采用 adaptive；多模态默认 adaptive，Lite 默认 16:9。
- 未传递 Max 专属扩写选项、水印和回调地址，采用供应商默认行为；后台通过查询接口轮询结果。
- 单图默认首帧，多张图默认参考图；显式指定角色优先。首尾帧与参考图片、视频、音频冲突时报错要求澄清，不丢弃素材。
- 新视频明确要求 2K 时直接生成 2K。已有本应用 H3 768P 成功产物才走再生成，保留最终提示词及全部原始素材。
- 输入框支持上传、引用历史图片/视频/音频；发送后在文字下方显示 64×64 缩略图，点击可查看原素材。

## 启用

1. 使用项目要求的 Java 26 构建后端。服务运行环境需安装 `ffprobe`，并保证服务进程可执行；本机已经安装并验证。部署环境可通过下表指定绝对路径。
2. 启动新版后端，Flyway 自动执行 `V20261026_01__video_v2_tasks.sql`。迁移添加 IR 文本和并发版本字段，扩展任务 ID 长度，恢复旧版中断的转存轮询；不删除任务或资源。
3. 构建并运行新版前端。已运行的旧后端需要重新启动后才会使用本次工具和迁移。
4. 使用已开通相应视频模型的 MiniMax API 账号；本次验证没有调用收费生成接口。

以下是 Spring 配置项及对应的**进程环境变量**。除现有 API key 回退外，仅在仓库 `.env` 中新增这些可选参数不会自动导入 Spring；应导出给服务进程，或直接修改 `application.yml`。

| Spring 配置 | 环境变量 | 默认值 |
| --- | --- | --- |
| `generation.minimax.default-video-model` | `MINIMAX_VIDEO_MODEL` | `MiniMax-H3` |
| `generation.minimax.video-v2-base-url` | `MINIMAX_VIDEO_V2_BASE_URL` | `https://api.minimax.cn` |
| `generation.minimax.ffprobe-path` | `MINIMAX_FFPROBE_PATH` | `ffprobe` |
| `generation.minimax.regeneration-task-id-enabled` | `MINIMAX_REGENERATION_TASK_ID_ENABLED` | `false` |
| `generation.minimax.api-key` | `MINIMAX_API_KEY` | 兼容原有 key 读取方式 |

V1 的 `MINIMAX_BASE_URL` 保持独立。未指定 V2 地址且 V1 地址为自定义网关时，V2 也使用该网关，便于代理和本地契约测试。

## 聊天操作

可直接说“参考这些素材生成 15 秒视频”“只优化这段视频提示词”“先优化再生成”“把刚才的 H3 768P 视频生成为 2K”“查询我的视频任务”“取消这个排队任务”。

两套 Agent 使用相同工具名：`generate_video`、`query_video_task`、`list_video_tasks`、`cancel_video_task`、`delete_video_task_record`、`regenerate_video2_k`、`list_video_inputs`。

`generate_video.operation` 的 `h3_context_ir` 只返回增强提示词；只有用户同时要求优化并生成时才使用 `enhance_then_generate`。串联生成具有稳定任务 ID，中断恢复不会重复提交。IR 输出超过普通生成接口 7000 字限制时保留完整文本并说明失败，不截断后收费生成。

高级素材角色使用 `referencesJson` 数组，例如 `[{"resourceId":"资源ID","role":"first_frame"}]`；留空读取当前消息全部媒体，显式 `[]` 表示纯文本请求。仅接受当前用户已有的资源 ID，不接收任意外部 URL。任务工具接收本应用 taskId，可通过列表获取；列表支持分页和状态、模型、任务类型筛选。

## 素材校验

上传上限为单文件 50 MiB。已补充 HEIC/HEIF/MOV 文件签名识别；浏览器是否能预览这些格式取决于其解码支持。生成前读取归属当前用户的真实文件并用 ffprobe 校验，不信任数据库中的尺寸。

| 素材 | 单文件上限 | 主要限制 |
| --- | --- | --- |
| 图片 | 30 MiB | JPEG/PNG/WebP/HEIC/HEIF；宽高 256–5760；比例 0.4–2.5；参考图最多 9 张，首尾帧各 1 张 |
| 参考视频 | 50 MiB | MP4/MOV；H.264/H.265，音轨 AAC/MP3；23.976–60fps；每段 2–15 秒，最多 3 段且合计不超过 15 秒 |
| 参考音频 | 15 MiB | WAV/MP3；每段 2–15 秒，最多 3 段且合计不超过 15 秒 |

私有素材通过 data URI 传递，整个 JSON 请求含 Base64 后不得超过 64 MiB；接近上传上限的视频可能超过编码后的请求限制，会明确拒绝并要求减小素材，不静默裁剪。视频宽高与比例也按文档校验。

2K 再生成默认使用本应用保存的 `base_video`，校验 H3 768P 源任务、音轨、24fps、32 倍数尺寸、像素面积与合法帧数。362 帧的合法源视频约 15.083 秒，不套用普通参考视频 15 秒上限。只有账号已开通 `source_task_id` 白名单时才启用配置项；此路径限定 7 日内未删除的源记录。

文档对单独尾帧的描述不完全一致。显式尾帧按用户指定的角色传递，不擅自改成首帧；以供应商实际校验为准。

## 取消、失败与恢复

- 停止聊天不取消视频。仅排队任务可取消，运行中任务继续等待回填。
- 删除供应商记录必须由用户明确要求，且只允许成功/失败记录；成功结果尚未转存时拒绝删除。本地已保存视频始终保留。
- 查询与 DELETE 存在状态变化窗口，供应商可能返回 `deleted` 而非 `cancelled`。工具返回实际 action，不把删除误报为取消成功。
- 创建超时、5xx、缺少 taskId 或创建进程中断时记录 `SUBMISSION_UNKNOWN`，不自动重发收费 POST。已知任务可恢复轮询、IR 串联和转存。
- 所有任务与素材均按用户隔离。供应商共享 key 的列表同时限制本地所属 ID，并对返回结果再次过滤。
- 查询和转存遵守 7 日窗口，产物及时保存到本地资源存储。转存中断有租约恢复；并发更新通过版本号防止覆盖取消/完成状态。

## 验证

覆盖了六类 HTTP 契约、V1/V2 路由、模型与角色约束、提交结果不明、用户隔离、取消/删除、IR 及稳定串联 ID、恢复和真实媒体校验。另有两套框架的工具注册测试、Harness 子会话回填测试，以及前端真实 SDK 消息渲染测试。

本次使用本地 HTTP fixture 和合成媒体测试，未消耗 MiniMax 视频额度；尚未对真实账号的模型权限、白名单和最终成片作收费验证。PostgreSQL 集成用例需要单独配置测试数据库，本次未对运行中的业务库执行迁移。

2026-10-27 最终结果：后端选定回归共 228 项，227 通过，1 项因缺少 `AGUI_TEST_DB_URL` 跳过；前端 160 项全部通过，eslint 与生产构建通过。真实浏览器核验三类引用素材均为文字下方的 64×64 缩略图。
