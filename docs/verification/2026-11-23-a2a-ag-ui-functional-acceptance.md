# H Agent A2A 与 AG-UI 手工功能验收

功能对应 [统一实施目标](../specs/2026-11-20-a2a-ag-ui-integration-goals.md)。每条用例可记录为通过、失败或阻塞。模型生成的措辞可以变化，以任务状态、权限、产物和业务回执为准。

## 测试准备

- 使用独立验收数据库、Redis 和测试账号。准备普通用户 A、与 A 独立的普通用户 B，以及具有 `A2A_LONG_FORM` 或 `ADMIN` 角色的用户 C。权限用例可使用两个浏览器配置分别登录。
- 启用 `NACOS_ENABLED`、`NACOS_A2A_ENABLED`、`OTHER_AGENTS_A2A_ENABLED`、`A2A_STORY_ENABLED` 和 `A2A_DOCUMENTS_ENABLED`。`backend` 与 `other-agents` 使用同一项目数据库、MinIO 和 `A2A_STORY_SIGNING_KEY`。签名密钥至少 32 字节。填写 `other-agents` 可达的 `A2A_DOCUMENT_CALLBACK_URL`，路径为 `/api/internal/a2a/document-updates`。正式验收前确认两个服务的 Flyway 迁移成功，Nacos 中能看到故事创作、插画、审稿、事实核查和文档 Agent。配置项见 [.env.example](../../.env.example)。
- 准备一份正文含 `UAT-TEXT-01` 的文本 PDF，以及一份两页扫描 PDF。扫描件第二页放一个肉眼可辨的表格，包含 `UAT-SCAN-02`，另准备模糊版触发待复核。文档用例需要 OCR 配置，插画和视频用例各需对应的生成服务。链路查看用例需要可用的 Langfuse。
- 从「新会话」分别创建远端故事助手、普通聊天、Harness 和订单处理助手会话。订单场景使用项目现有订单 MCP 的内置数据，建议使用尚未执行过订单操作的测试账号。

## 1. 远端故事创作、追问和插画

这三项在「A2A 远端故事助手」输入自然语言即可。PDF 解析和文档画布从第 4 组的通用助手或个人 Harness 入口验证。

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 01A 追问与续接 | 在「A2A 远端故事助手」发送「写一个发生在月球基地的故事」。收到追问后刷新当前会话，回复「面向 8–12 岁儿童，轻松幽默的科幻风格」。 | 追问仍在原会话，补充后能继续出稿。查服务日志时，追问和续接使用同一个 A2A 任务 ID。 |
| 01B 流式与断线恢复 | 在生成较长正文时观察聊天。首段文字出现后，在浏览器开发者工具切换为离线，再恢复网络并重新打开原会话。 | 在线时能看到正文逐段追加。恢复后能看到原任务进度或完整故事，已出现的段落没有重复拼接，历史中只出现一份完整回答。 |
| 01C 修订和插画 | 在完成的故事后说「把刚才的故事结尾改成主角和机器人一起回基地，保留前文」，等待完成，再说「给刚才的故事画一张插图」。 | 原初稿仍可查看，新回复标为「修订稿」。插画落在原会话，刷新后仍可打开。用 B 打开 A 的图片资源地址或原会话，访问被拒绝。 |

## 2. 按技能发现与多跳审核

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 02A 评分与核查 | 先说「给这段稿子打个分：月球基地的孩子用一盏旧灯找回了机器人」。再说「请核查稿件中的事实：月球基地有 20 名居民，建于 2040 年。参考资料：登记册记载基地有 20 名居民，未注明建造年份。」 | 评分包含分数与理由。审核区分有资料支持的人数和证据不足的建造年份。启用追踪时，Langfuse 能关联 backend、审稿和事实核查调用。 |
| 02B 动态发现与降级 | 在可独立启停的验收实例上，先撤下审稿 Agent 的在线端点，等待 Nacos 更新后再次请助手审核稿件。恢复审稿、单独撤下事实核查端点后再次请求。最后恢复两个端点再试。 | 第一阶段提示没有在线审核技能。第二阶段能区分下游核查失败和证据不足。端点恢复后，新请求可重新完成审核。 |

## 3. 私有技能和任务权限

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 03A 按角色发现与使用 | 用 A 和 C 分别在远端故事助手问「你能做哪些事？」，随后分别说「请用长篇小说模式为 12 岁读者写一章悬疑科幻小说，主题是火星图书馆」。 | A 的技能列表不显示长篇模式，请求被拒绝。C 可以发现长篇模式并生成一章。公开 AgentCard 也只展示基础技能。 |
| 03B 越权访问 | 在接口验收工具中，用为 B 签发的测试身份尝试查询、订阅、续接或取消 C 的长篇任务。保留 C 的任务 ID，逐项核对响应。 | B 无法读取任务状态、正文和产物，无法通过续接或取消改变 C 的任务。C 仍可查询自己的任务。 |

## 4. 远端文档和协作画布

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 04A 解析与区域复核 | 在普通聊天上传文本 PDF，发送「请解析这个 PDF，告诉我正文所在的页码」。再上传扫描 PDF，请助手进行 OCR 和质量复核。进入待复核任务，对第二页问题区域点「重新识别这一区域」，对照原文后点「采用为人工修正」并提交。 | 解析和复核显示为原会话的任务。能定位对应原文页，复识别只返回选中区域的候选文字。确认后解析出的 `UAT-SCAN-02` 与原文一致。 |
| 04B 画布续写和导出 | 在聊天顶部打开「文档画布」，选中已复核任务并点击「导入到空白画布」。手工修改第二段，加上 `UAT-CANVAS-01`，保存。选中修改内容点击「引用所选」，提问这段写了什么。再在画布填写续写要求，点击「让 Agent 续写当前稿」，之后点「导出到会话」。 | 聊天能识别被引用的段落。续写保留用户的第二段修改。刷新后画布内容与版本仍在，原会话生成的 DOCX 与最终保存版本一致。也可在新会话空白画布中直接开始。 |
| 04C 并发编辑 | 用同一账号在两个标签页打开同一会话画布。分别修改，然后先保存标签页 1，再尝试保存标签页 2。 | 标签页 2 显示版本冲突，可查看最新版本并找回或复制未保存编辑。标签页 1 的已保存内容未被覆盖。 |

## 5. 个人任务看板和长任务恢复

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 05A 回填与权限 | 并行提交一次远端文档解析、一次短视频生成，并按 10A 发起自动化试跑。关闭聊天页。重新登录，打开「个人任务」`/tasks`，分别筛选文档、视频和自动化。用 B 登录查看同一页面。 | A 能看到三个任务的真实状态与来源，可返回原会话，打开已生成视频、查看文档和试跑回执。B 看不到 A 的任务。 |
| 05B 回调失败与重启 | 在验收环境暂时拦截文档回调路径，使其返回 `503`，保留任务查询入口。提交扫描 PDF，在处理中重启 `other-agents`。记录原任务 ID，恢复回调，再刷新看板和原会话。 | 回调中断期间仍能读取已保存状态。重启后原任务可继续执行，恢复回调后出现成功回执。同一任务只交付一份结果。 |
| 05C 取消与重试 | 对一份仍在解析或复核中的文档点击「取消原任务」，刷新原会话。另找一条已失败且显示重试操作的文档，恢复服务后点击重试。若看板有排队视频并显示取消按钮，可另测视频取消。 | 取消显示实际结果，已取消任务不再自动交付。可重试文档恢复进度。视频的按钮与最终结果以供应商状态为准。 |

## 6. 工具调用与历史

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 06A 同名工具独立展示 | 在普通聊天或 Harness 发送「请分别用两次知识库搜索查询 `UAT-SEARCH-A` 和 `UAT-SEARCH-B`，最后告诉我每次查到了什么」。展开执行过程，结束后刷新。 | 两次同名调用各有自己的参数、结果及状态。运行时逐步展示可用参数，刷新后历史仍能区分两次调用，页面不显示未公开字段或运行时凭据。 |
| 06B 错误状态 | 上传一份小文本文件，再要求助手分别读取已上传文件和一个不存在的路径。检查执行过程和刷新后的历史。 | 成功和失败分别归属到对应调用。参数收集结束时，该步不会提前显示执行成功。 |

## 7. 订单与工单逐项处理

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 07A 多选与逐项决策 | 打开「订单处理助手」，在输入框选择「订单或关联工单」，选取 `ORD-DEMO-003`、`ORD-DEMO-004` 和一张已存在的工单，点「引用所选」。发问「逐项检查，给出建议，涉及写操作先等我确认」。可在地址卡片补充完整地址，生成独立改址方案。 | 输入框展示所选对象，助手按各自订单和工单查询并返回建议。地址修改生成对应订单的单独确认项。 |
| 07B 待确认恢复与幂等 | 准备至少两个独立待确认方案。确认一项，拒绝另一项。有第三项时保留待处理，刷新后再处理，观察操作轨迹。 | 每个决定只影响对应事项，回执可查。未处理项刷新后仍可操作，重复点击或旧确认卡片不会重复执行业务动作。 |

## 8. Harness 分支协作

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 08A 查看与停止分支 | 在个人 Harness 发送「请委派三个独立子 Agent，分别整理资料、比较两种方案、检查假设，最后由主 Agent 汇总」。运行后从界面进入分支，查看委托和工具记录。若仍有分支在运行，在该分支内点停止，刷新。 | 能回到原分支，看到委托、进度和已有产物。停止单个分支不会取消其他分支，主会话能区分已收集结果和缺失结果。 |
| 08B 只重试失败分支 | 准备一组同时含已完成与失败分支的会话。打开失败分支，点击「重试分支」，结束后回主会话要求根据已有分支结果汇总。若测试环境只能复现手动停止，等待已有失败样本再测本项。 | 重试在原失败分支执行，已完成兄弟分支保留原结果和状态，主会话可使用新旧分支结果。 |

## 9. 知识库增量编辑与来源核对

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 09A 逐段采纳 | 请 Harness 把一份至少三段的测试说明保存为 Agent 知识条目。到「个人 → 知识库」打开条目的修订入口。勾选两段，填写修改要求及一条已有、可访问的来源引用。生成草稿，点来源按钮核对原文，修改一个建议，只勾选一段提交。 | 草稿只涉及选中范围。可查看有权限的来源原文。新版本只采用被确认的段落，版本记录和来源可查。 |
| 09B 冲突和来源隔离 | 同一条目在两个标签页各生成草稿。标签页 1 先提交，标签页 2 再提交旧草稿。另用 B 尝试打开 A 的编辑页和来源。 | 标签页 2 提示条目版本已变化，能对照新版本并查看自己的草稿。B 无法访问 A 的条目和来源。 |

## 10. 自动化提案编辑与试跑

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 10A 同一提案与独立试跑 | 在普通聊天输入「每周一上午 10 点，按 Asia/Shanghai 时区生成一段示例巡检摘要。首行为 `UAT-AUTO-01`，仅返回文本」。在「自动化」页打开提案，改为上午 9 点并保存。回原会话询问「读取这条提案的最新日程和执行会话」。随后点「试跑当前提案」，再到 `/tasks` 查看。 | 聊天与页面指向同一提案，Agent 能读到更新后的日程。试跑产生含 `UAT-AUTO-01` 的结果，提案仍待确认。对同一版本重复发起试跑可复用已有试跑记录。 |
| 10B 确认最终版本 | 在原会话请 Agent 把试跑提案的首行改为 `UAT-AUTO-02`。在自动化页面核对时区、每周一 9 点及能选择的执行会话，确认启用。可同时保留旧标签页，尝试确认旧版本。验收结束后停用测试任务。 | 页面能看到 Agent 修改后的提案。生效任务使用最后确认的指令、时区及执行会话。旧版本提交提示刷新，不能覆盖已确认设置。 |

记录失败时，附用例编号、普通或授权账号身份、操作时间、会话或任务 ID、看到的提示，以及能复现问题的输入。截图和日志中遮挡签名密钥、访问令牌与真实业务数据。
