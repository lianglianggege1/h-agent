# 中国大陆智能营销场景的智能外呼调研

调研日期：2026-09-11。仅参考官方产品文档、厂商公开案例和政策原文；未读取或参考本仓库的智能语音实现。企业规模分类是基于集成方式的方案归纳，不是市场份额或普及率统计。

## 结论

从阿里云、腾讯云和容联七陌的公开能力看，外呼应作为一套业务流程理解：**名单进入 → 建立批次与策略 → 电话线路执行 → 人机接待 → 结果回流 → 后续跟进**。AI 对话只是执行环节之一，自动拨号接人工也属于智能化外呼。用户后续增加的电话表适合作为名单入口与运营界面，后台需要保留任务和每次拨打记录。[阿里云集成流程](https://help.aliyun.com/zh/outboundbot/developer-reference/quick-integration)、[七陌外呼任务](https://help.7moor.com/docs/%E5%91%BC%E5%8F%AB%E4%B8%AD%E5%BF%83/%E6%96%B0%E6%89%8B%E5%BC%95%E5%AF%BC/%E9%80%9A%E8%AF%9D/%E5%A4%96%E5%91%BC%E4%BB%BB%E5%8A%A1%E5%A6%82%E4%BD%95%E4%BD%BF%E7%94%A8/)

## 小、中、大公司的采用思路

以下是设计建议，不代表每个规模的企业都这样采购；实际选择取决于业务复杂度、客户量、研发能力和部署要求。

| 企业情况 | 可采用的方案 | 自己重点负责什么 |
| --- | --- | --- |
| 小公司、少量销售、尚无成熟 CRM | 采购 SaaS 外呼/联络中心，上传 Excel/CSV，配置批次、话术和人工跟进；先跑通单一场景 | 号码来源、场景、名单质量、人工成交跟进；避免起步就建设电话底层 |
| 中型公司、已有 CRM 或营销系统 | 自有名单与任务界面，通过 API 接机器人/云联络中心，必要时嵌入电话条 | 分群、去重、跨任务频控、任务编排、结果回填、线索分配与转化分析 |
| 大公司、多事业部、多渠道或已有呼叫中心 | 自有客户运营平台，集成既有坐席与号码资源，按部署约束采购云服务或定制方案 | 统一客户身份、授权和禁呼、组织权限、质检、审计、容量与故障恢复；必要时做多个服务商适配 |

这些方案都有产品能力依据：七陌提供控制台导入与任务管理，也提供自有 CRM 的 API 和软电话条集成；其公开新东方案例描述了 CRM 内嵌电话条、批量外呼和通话记录回推。因此，大企业也可以采购通信能力并自建业务流程，规模大不等于从头自研。[七陌 CRM 集成](https://developer.7moor.com/callinCrm/)、[七陌历史教育案例](https://developer.7moor.com/educationCase/)

## 已核实的产品模式

**阿里云智能外呼机器人：任务 API + 异步结果。** 官方流程是创建任务组、批量加入号码、查询结果及通话详情；可用 RocketMQ 接收事件，通话结束、标签就绪、录音就绪是不同事件。接入端不能假设所有数据在一次 HTTP 回调中同时到齐。官方状态还区分未接通、空号、频次限制、禁呼和转人工等情况。[快速集成](https://help.aliyun.com/zh/outboundbot/developer-reference/quick-integration)

**腾讯云联络中心：批次运营配置较完整。** 官方批量智能体任务支持导入号码及动态变量、选择号码顺序或随机呼叫、设置并发和呼出时段、暂停/继续及查看结果。文档当前规定未接听可选不重呼或重呼一次，并可设间隔；智能体外呼要求接入自有电话。这说明重试能力与号线条件需要逐供应商核实。[创建批量智能体任务](https://cloud.tencent.com/document/product/679/128336)

**容联七陌：名单池 + 自动拨号 + 人工坐席。** 官方明确外呼任务名单独立于客户；导入时可按当前任务或全部任务去重。普通任务先呼通坐席再呼客户，批量任务先呼客户再接坐席，并发可按空闲坐席控制。该模式不能直接当成 AI 机器人对话能力。CRM 集成支持事件推送或主动查询通话记录。[外呼任务](https://help.7moor.com/docs/%E5%91%BC%E5%8F%AB%E4%B8%AD%E5%BF%83/%E6%96%B0%E6%89%8B%E5%BC%95%E5%AF%BC/%E9%80%9A%E8%AF%9D/%E5%A4%96%E5%91%BC%E4%BB%BB%E5%8A%A1%E5%A6%82%E4%BD%95%E4%BD%BF%E7%94%A8/)、[CRM 集成](https://developer.7moor.com/callinCrm/)

## 对未来电话表的建议

建议页面仍围绕一张名单表操作，但后台分开管理以下对象：

| 对象 | 建议保存的内容 |
| --- | --- |
| 外呼名单 | 号码、姓名、业务变量、来源、授权依据、负责人、当前跟进状态 |
| 外呼任务 | 本批目标、名单快照、话术版本、线路/服务商、执行时段、并发和重试策略 |
| 单次通话 | 内外部任务 ID、通话 ID、尝试次数、接通状态、失败原因、时间、时长、录音和摘要 |
| 跟进记录 | 业务意向、预约时间、人工负责人、处理结果 |
| 禁呼记录 | 禁呼原因、时间、范围及生效状态，发起新呼叫前再次校验 |

“已接通”和“有意向”应为两个字段；“未接听”也不能自动等同于“无意向”。一次名单入选可能产生多次拨打，不能用一行最新结果覆盖历史。供应商异步事件应幂等处理，并保留主动查询补偿路径。以上为根据官方任务与事件模型提出的系统设计建议。

建议第一阶段选择一个明确场景和一个服务商，提供“导入/筛选名单 → 创建外呼任务 → 查看结果 → 分配人工跟进”，并预留可替换的服务商接口。先验证接通后有效沟通、意向判定准确性、人工承接和最终转化，再扩大并发；不要只以拨打量判断效果。

## 中国大陆落地边界

《消费者权益保护法实施条例》第二十四条要求：未经消费者同意不得拨打商业性电话，应提供明确、便捷的取消方式，取消后立即停止。号码表因此需要记录授权依据和拒绝联系状态；已有手机号不等于可以营销外呼。[国务院条例原文](https://app.www.gov.cn/govdata/gov/202403/19/513111/article.html)

工信部信管〔2020〕81号针对经营呼叫中心业务，明确不允许商业营销类电话呼出；同时，企事业单位依托网络设备为自有客户提供服务等活动不属于该通知所称经营呼叫中心业务。两种适用对象不能混同，也不能据此推导“消费者同意 + 买外呼平台”就允许任意营销。具体业务性质、线路资源及供应商准入需共同核实。[工信部通知原文](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2020/art_5252be6730fa47ebbfd726c58648e733.html)

阿里云文档要求企业实名认证，支持 SIP 自带线路或第三方号码资源；号码及话术资料存在审核要求。购买机器人能力与取得适合该场景的可用电话线路是不同事项。供应商历史案例只能证明集成方式，不能证明某行业场景如今仍可直接获准开通。[阿里云接入准备](https://help.aliyun.com/zh/outboundbot/product-overview/preparations)
