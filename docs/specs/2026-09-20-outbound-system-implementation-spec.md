# 智能外呼实施规格（个人项目首版）

创建：2026-09-20；审查修订：2026-09-21
状态：待实施。技术路线已确定，双向媒体模块与实际 Agent 电话链路尚待验证。
关联：[统一架构设计](2026-09-11-unified-voice-and-outbound-architecture.md)、[会话绑定语音设计](../design/2026-09-11-session-bound-voice-agent-design.md)。

## 1. 首版目标与边界

**导入测试分机 → 选择 Agent、填写沟通目标 → 手动启动 → 软电话接听并多轮交谈、可插话 → 挂断 → 查看结果和有效对话。**

沿用 **FreeSWITCH + 双向 WebSocket 媒体 + 现有 Python 语音流水线 + Java Agent**。首版按本次范围仅验证注册软电话，不拨打真实手机号；这能验收自有 Agent 的电话对话闭环，但不能宣称已完成客户手机外呼。后续接入运营商 SIP 中继，不另建容联 REST 拨号实现。

范围固定：

- 一个后端调度实例、一个 FreeSWITCH、一个电话 Worker；全局最多一通外呼。
- 一批最多 100 个分机，每项只提交一次拨号，无自动重拨。再次拨打须另建任务。
- 只适配已验证的 HARNESS_STREAMING 顶级 Agent；保持浏览器 LiveKit 语音原有行为。
- 三张新增业务表，复用 Agent Session、voice_calls、voice_turns 和 Agent Run。
- 页面只有“名单”和“任务”两个视图，通话详情放在任务内。

首版不做：真实 PSTN 线路、任意 SIP URI、录音归档与播放器、意向标签、CRM 跟进、统计看板、预约、自动摘要、可配置并发、分布式锁、消息队列、多供应商抽象。临时音频不是业务录音，不提供下载入口。

本规格优先于此前外呼页面设计中的扩展功能；部署命令、完整 SQL、DTO 和第三方协议逐字段说明留在实现及部署文档中，避免多份定义漂移。

## 2. 本次审查修正

| 原方案问题 | 修正 |
| --- | --- |
| 把录音文件增量读取和未经测量的 200–500ms 延迟作为实时链路保证 | 恢复双向媒体流；先验证收音、回灌、打断与播放结算 |
| 把停止播放写成 uuid_broadcast stop，甚至用 uuid_kill 处理插话 | 插话停止播放并清空缓存，保留通话；挂断单独处理 |
| 接听后才创建会话、准备语音，直接复用普通聊天入口 | 拨号前准备独立 Session、PHONE 通话与实际 Harness 执行能力 |
| contact_ids 数组、通话记录、累计计数同时维护进度 | 创建任务时预建通话条目；进度从条目聚合 |
| 禁呼联系人不参与唯一约束，重复导入可绕过禁呼 | 联系人按用户和分机无条件唯一，重复导入不修改禁呼 |
| Redis 锁到期或 finally 直接释放占用，超时强制判失败 | 数据库约束单并发；远端和本地执行均结束才释放，无法确认则 UNKNOWN |
| 重复结束事件递增计数并触发下一通 | 幂等合并事件，由单路调度读取数据库决定下一通 |
| 录音、意向、统计挤入首版，页面却缺名单管理 | 两个视图覆盖导入、执行、查看结果，删除运营功能 |

## 3. 架构与代码复用

~~~mermaid
flowchart LR
    UI["名单 / 任务"] --> OUT["Java outbound<br/>任务、调度、电话事实"]
    OUT <-->|ESL 控制与事件| FS["FreeSWITCH"]
    FS <-->|SIP / RTP| PHONE["注册软电话"]
    FS <-->|双向 WebSocket 音频| PY["Python 电话音频适配<br/>共用 VAD / ASR / TTS"]
    PY <-->|轮次、可播文本、播放结果| VOICE["Java voice<br/>通话与轮次"]
    VOICE <--> AGENT["现有 Harness Agent"]
    OUT --> DB[("PostgreSQL")]
    VOICE --> DB
~~~

职责保持三处：

- **outbound**：名单、任务、单路调度、ESL 呼叫控制及电话结果；一个业务入口即可，不按每张表拆一套模块。
- **voice / Agent 执行适配**：会话身份、轮次幂等、真实 Agent 执行、取消与有效对话提交。外呼不再维护第二套对话引擎。
- **realtime-voice**：复用现有 ASR/VAD/TTS 和轮次交互，增加电话音频输入输出。媒体编码、缓冲、停止播放和连接清理集中在此适配中。

本次已核对的必要改造：

| 现有代码 | 当前限制与首版调整 |
| --- | --- |
| VoiceCallModule | 当前只接受 standard-chat，并创建 LiveKit 房间；增加 PHONE 生命周期，清理按渠道处理 |
| VoiceTurnModule / AnthropicVoiceReply | 当前是直接模型回复且无工具；接入真实 Harness 执行，复用轮次与消息身份，不能静默回退成普通模型 |
| HarnessAgentExecutor | 当前生成完成即写 assistant 消息；电话回复改为按播放结果提交，避免提前写入未播全文 |
| realtime_voice/worker.py | 入口依赖 JobContext 和 room；提取共用流水线，在现有 src/realtime_voice 包内增加电话入口和 I/O 适配 |
| voice_calls / voice_turns | 房间等字段当前强制存在，首轮也要求用户消息；按渠道调整，支持无虚假用户消息的 Agent 开场 |

沿用现有 JdbcTemplate、事务、ApiResponse、登录鉴权和 apiFetch。不要为了电话接入重写浏览器语音，也不要求一次适配所有 Agent 类型。

## 4. 先验证双向媒体

ESL 负责呼叫控制和事件，音频通过选定媒体模块传输；ESL 连接成功不代表能双向交谈。[FreeSWITCH ESL 文档](https://developer.signalwire.com/freeswitch/integration/event-socket/)

实施第一步只用一个注册分机验证以下四项，通过后固定 FreeSWITCH、媒体模块与 SDK 版本：

1. 持续收到客户侧音频，不能把系统自身播报混入客户 ASR；编码和采样率显式转换，不假定 SIP 音频天然就是 ASR 所需 PCM。
2. 能持续回传并播放 TTS 音频；播放期间仍可监听客户发言。缓存有界，持续拥塞时结束通话，不能越积越多。
3. 插话能停止并清空 Python 和 FreeSWITCH 两端的旧音频，旧回复不会在下一轮恢复。
4. 能获得与具体回复对应的播放完成/中断结果，并验证媒体断开及控制端失联后的挂断。

媒体模块只选一个实现。mod_audio_stream 可作为候选，但其社区版与双向发行版能力不同，须核对实际制品、许可及播放控制协议，不能仅凭仓库名称假定可回灌。[模块说明](https://github.com/amigniter/mod_audio_stream)

现有项目固定 livekit-agents==1.6.9；先验证该版本自定义 I/O 与播放结算能适配电话，再提取共用代码。保留 SDK 是优先复用方向，不是已经验证的结论。

删除文件 tail 方案、固定跳过 44 字节 WAV 头、未经测量的延迟承诺，以及“文件 → WS → RTP”的多阶段建设计划。首版交付一条经过验证的双向链路。

**停止播放不等于挂断。** FreeSWITCH 标准播放可使用 uuid_break，uuid_kill 用于结束通话；媒体模块自有队列按该模块协议停止、清空，不能假定标准命令也会清空它。[FreeSWITCH 命令参考](https://github.com/signalwire/freeswitch-docs/blob/main/docs/reference/cli-and-api.mdx)

安装步骤在验证后形成一份可重复部署说明，记录 SIP/RTP 地址与端口、ESL 访问限制、媒体连接及超时配置。规格不提供未经运行的 brew/Docker 命令，不保留默认密码；ESL 与内部控制端点仅向受控网络开放。

## 5. 最小数据模型

以下定义概念和必要约束；具体字段类型、映射类与迁移以实现为准。

| 对象 | 必须保存的信息 | 约束 |
| --- | --- | --- |
| 联系人 outbound_contacts | id、user_id、分机 phone、姓名、授权依据 consent_basis、禁呼 dnc、创建时间 | (user_id, phone) 无条件唯一；授权依据非空 |
| 任务 outbound_tasks | id、user_id、request_id、名称、Agent 绑定快照、沟通目标、状态及原因、创建/更新时间 | (user_id, request_id) 唯一；创建后不编辑执行内容 |
| 通话条目 outbound_calls | id、task_id、contact_id、user_id、分机/姓名快照、voice_call_id、阶段、接通结果、对话结果、原因、必要时间 | (task_id, phone) 唯一；归属一致；voice_call_id 唯一并关联 voice_calls |

创建任务时，在同一事务中为去重后的每个联系人插入一条 QUEUED 通话条目。它同时表达计划和唯一一次拨打尝试，无需第四张 task_items 表，也无需 contact_ids 数组。跳过、取消和未接听均保留该条目；进度实时聚合，不维护 completed_count++。

保留几个容易混淆的概念：

- **通话身份**：outbound callId 在拨号前生成，作为该次单通道外呼的 origination_uuid；异步任务 Job-UUID 是命令关联身份，不能当作电话 UUID。若实现保留独立的 FreeSWITCH ID 字段，则必须在发送前固定映射。[通道变量说明](https://developer.signalwire.com/freeswitch/reference/channel-variables/)
- **Agent Session**：每通电话独立，关联在 voice_call 上；不继承操作者聊天，不让不同客户共用上下文。创建过程不能归档或切换操作者的其他会话。
- **接通结果**：CONNECTED / NO_ANSWER / BUSY / FAILED / NOT_DIALED / UNKNOWN；**对话结果**：COMPLETED / INTERRUPTED / FAILED / NOT_STARTED / UNKNOWN。接通不等于对话成功。
- **时间事实**：提交意图、接听、远端结束、本地结案分别记录；未知挂断时间留空，不用本地清理时间计算通话时长。

数据库通过用户归属约束、任务内号码唯一、全局活跃通话部分唯一索引兜底，并约束最多一个 RUNNING 任务。PREPARING、DIALING、ACTIVE、ENDING、UNKNOWN 全部占用名额；READY/RUNNING 等任务状态不代替电话占用。

voice_calls 增加 BROWSER/PHONE 渠道，PHONE 不伪造房间或普通聊天 prompt；创建 Session、voice_call 与通话关联在同一事务完成。活跃电话 Session 保留现有并发保护，并避免被其他会话切换或过期归档中断。

新增业务时间使用带时区时间，接口返回 ISO 8601；现有 voice 的毫秒时间保持原样。新增 Flyway 迁移前检查版本，不改已执行迁移，不用 IF NOT EXISTS 掩盖结构不一致。

## 6. 执行流程与异常收尾

### 6.1 任务和通话阶段

任务：**READY → RUNNING → COMPLETED**；运行故障进入 **PAUSED**，用户可继续；用户停止后为 **STOPPED**。首版同时最多一个 RUNNING 任务，其他任务启动时返回忙，不做后台任务排队。

通话：**QUEUED → PREPARING → DIALING → ACTIVE → ENDING → FINISHED**。不能确认远端或本地执行是否结束时进入 **UNKNOWN**。未拨出的跳过/取消直接 FINISHED，以 NOT_DIALED 和原因区分。

只保留“启动/继续”和“停止”两个任务操作。停止会取消剩余 QUEUED 条目，并请求结束当前通话；任务 STOPPED 表示不再继续拨打，当前电话仍显示 ENDING/UNKNOWN 直到确认结束。重复操作无新副作用；COMPLETED/STOPPED 不可重新启动。

### 6.2 正常流程

1. **认领**：单实例定时调度读取 RUNNING 任务。在短事务内检查占用、用户归属、禁呼，选取一条 QUEUED 并进入 PREPARING。
2. **准备**：建立独立 Agent Session、PHONE voice_call 和关联；验证 Agent、Worker、ASR/TTS 与媒体服务可用。此时不拨号、不生成开场；实际媒体连接可在接听后建立。
3. **提交**：再次检查任务未停止、联系人未禁呼。事务写 DIALING 与提交意图后，只发送一次 originate。这个提交点之后的停止或禁呼无法保证阻止拨出，应按挂断收尾。
4. **接通**：电话接听与媒体就绪两项事实齐备才进入 ACTIVE，并用固定轮次身份启动一次 Agent 开场；接听后媒体迟迟未就绪则挂断。
5. **对话**：客户发言确认后交给同一 Session 的 Agent，回复流进入 TTS；插话、取消和播放结算遵循下一节。
6. **结束**：停止生成、TTS 与媒体，确认 FreeSWITCH 通道及本地旧执行均结束，结算剩余轮次后才 FINISHED、释放名额。调度据此开始下一项；全部条目终结后完成任务，STOPPED 不再改写为 COMPLETED。

电话、Worker 和 Agent 网络调用均放在事务外。准备失败不拨号，结案并暂停任务；同用户浏览器语音占用冲突在准备时处理，不能接听后才发现无法创建 voice_call。

### 6.3 不能删除的可靠性规则

- **提交不是接听**：bgapi 受理、BACKGROUND_JOB 和 CHANNEL_ANSWER 表达不同事实。处理命令失败及终结事件，不能只等待 CHANNEL_HANGUP；CHANNEL_CREATE 也不证明对方正在振铃。[ESL 异步命令与事件](https://developer.signalwire.com/freeswitch/integration/event-socket/)
- **不自动重拨**：originate 超时、断连或提交后崩溃均可能已拨出，进入 UNKNOWN、暂停任务，不重发原命令。
- **不以超时冒充挂断**：心跳或状态陈旧触发检查、取消和挂断，不能直接标失败释放名额。FreeSWITCH 侧也设置独立的振铃与最长通话限制，避免 Java 失联后无限悬挂。
- **重复/迟到事件不回退状态**：事件只更新已存在的 callId，不重建会话、不重放开场、不直接递归拨下一个。已知接听事实不能被后续异常抹成“未接听”。
- **启动先恢复**：先暂停遗留 RUNNING 任务；未提交拨号的准备项清理结案，已提交项检查并收尾。不恢复旧音频或旧 Agent 运行，不自动继续剩余名单。
- **UNKNOWN 保留占用**：重连后的“通道不存在”不一定排除先前后台拨号仍会创建通道；须同时确认在途命令、远端通道及本地执行已终止。无法自动确认时提供人工核实结案，保留备注与未知历史结果。

单路定时调度同时处理准备、恢复与收尾，不引入 Redis TTL 锁或另一套事件调度器。这里只承诺单实例运行，不承诺多实例切换。

## 7. Agent、轮次与有效对话

首版必须运行选定 Agent 的真实 Harness 路径，并至少验证一次业务知识或只读工具调用。任务背景作为本通对话输入，不能覆盖 Agent 身份和工具权限。电话执行只开放明确允许的业务知识与只读能力，不继承操作者私人记忆、任意文件权限、后台委派或需人工批准的长任务。

最小语义：

- 开场属于 Agent 轮次，但不是客户发言；支持空 user_message_id 的开场类型。每轮复用同一套消息、Run 与 turnId，不同时由 voice 和聊天入口重复创建。
- 只播报明确面向客户的文本，思考、工具参数、工具结果和内部日志不进入 TTS。
- **生成完成与播放完成分开**。每轮结束即结算，不等整通电话挂断才提交消息；WS 发送成功不等于播放完成。
- 按可确认的完整短句保存已播内容；被打断的尾句或未知进度标记中断/未知，不把未播全文当作有效对话。首版不追求精确到字的对齐。
- 产品聊天记录与下轮 Agent 工作上下文都遵循同一播放结算结果；工具调用和工具结果作为执行事实保留，不能用“仅重建文本历史”丢掉工具状态。
- 插话取消旧生成并清空两端待播内容。旧执行退出、播放结算完成后才接受下一轮；无法可靠取消时结束通话，不让新旧回复同时写入。
- callId、turnId、回复身份和 Worker 代次用于重复请求及迟到事件校验。同一轮重试不再执行 Agent；旧 Worker 不得继续提交结果。

通话详情通过关联 Session 读取有效消息，通过 voice_turns 读取播放/中断状态；原始日志和未播草稿不伪装成客户听过的对话。

至少有一轮客户发言及 Agent 回复完成结算，并正常结束且无运行故障，才记对话 COMPLETED；仅接通或只播开场不算完成对话。

## 8. 最小管理入口与配置

所有管理接口沿用 /api/outbound 和现有登录态，后端校验用户归属。仅保留以下能力，不在本文重复全部 DTO：

| 对象 | 管理能力 |
| --- | --- |
| 名单 | 批量导入、分页查询、标记禁呼 |
| Agent | 列出当前用户可用且已验证电话能力的顶级 Agent |
| 任务 | 创建、列表、详情、启动/继续、停止 |
| 异常通话 | 重新检查；确认远端与本地执行均终止后的人工结案 |

输入与幂等底线：

- 首版只接受服务端配置允许的测试分机；前端不能传任意 SIP URI、拨号串、媒体地址或 ESL 命令。手机号接入留到 SIP 线路阶段。
- 导入 1–100 行，全部校验后批量写入；重复项跳过且不解除禁呼。首版不删除联系人或解除禁呼。
- 创建任务时去重联系人、校验归属及禁呼，冻结分机、Agent 配置与沟通目标；名称和目标必填并限制长度。
- 创建请求携带 requestId；同用户同 requestId、相同内容返回原任务，内容不同返回冲突。先查已有请求，避免重试因配置变化新建任务。
- 拨号前重查禁呼；已提交电话的“禁呼”只影响后续拨打，结束当前电话使用“停止”。

Python 控制接口沿用现有内部 Worker 鉴权、认领、租约及代次校验；按 PHONE 扩展准备/开场/清理，复用已有 turns、回复流、interrupt、playout、end。不新建匿名 transcript/vad 回调，不要求 Python 直接访问业务数据库。

页面为 frontend/app/outbound/page.tsx，API 封装放在 frontend/lib/outbound.ts，从 /me 增加入口：

- **名单**：粘贴分机、填写授权依据、导入、勾选和禁呼。
- **任务**：一个表单填写名称、Agent、沟通目标和名单；列表显示状态及已处理/总数。详情内查看每通接通结果、对话结果、原因和有效对话，提供继续、停止与异常核实。

详情打开时低频读取本地状态；无可用 Agent、媒体未就绪或有 UNKNOWN 占用时明确提示原因，不显示虚假的可执行状态。

配置只保留外呼开关、ESL 地址与凭据、允许分机范围、选定媒体模块/Worker 地址、内部令牌，以及准备、振铃、回复和最大通话超时。默认不开启拨号；关闭开关仍须继续已提交通话的收尾。凭据不写进文档、前端或日志。

## 9. 实施顺序与验收

按闭环顺序推进，不先铺全套页面和 CRUD：

1. **一通媒体验证**：软电话注册、ESL 拨号、双向音频、停止播放、播放结果和独立挂断；固定版本与可重复部署步骤。
2. **一通真实 Agent 对话**：补齐 PHONE 生命周期、独立 Session、Harness 执行和播放后提交；连续三轮对话、一次只读工具调用、一次插话。
3. **最小批量业务**：三张业务表、任务幂等、禁呼、单路调度、停止与重启恢复。每个条目复用步骤 2 的真实通话入口。
4. **两个页面视图**：串联导入、启动、结束和查看结果，回归浏览器语音与原文字聊天。

首版验收只检查以下关键行为：

| 场景 | 通过条件 |
| --- | --- |
| 正常闭环 | 两个注册分机依次拨打，各有独立 Session；任务完成，可查看有效对话 |
| Agent 能力 | 连续三轮使用本通上下文，真实只读工具执行可核验，内部输出不被朗读 |
| 插话 | 旧音频停止且不恢复；下轮上下文不包含未播全文，不丢失已完成工具事实 |
| 单并发 | 准备、拨号、对话、收尾及 UNKNOWN 均占用名额，不同时拨两通 |
| 幂等与禁呼 | 重复创建/启动/事件不多拨；禁呼后重新导入不能绕过限制；越权请求失败 |
| 失败与停止 | 拒接/未接听正常结案；准备失败不拨号；停止取消余项并收尾当前电话 |
| 失联与重启 | 不重发 originate、不自动继续任务；无法确认时保持 UNKNOWN，不靠超时释放 |
| 结果真实性 | 接通但 Agent 失败分别展示；无可靠时间不编造时长，未拨打不计为已拨打 |
| 现有能力回归 | 浏览器语音、原聊天、会话权限和消息读取行为不受破坏 |

记录实际首句响应时间和打断停止时间，用于判断体验与定位问题，不在技术验证前承诺固定延迟。完成上述验收后交付的是**软电话环境的完整 Agent 外呼闭环**；真实客户手机接入单独验收。
