# H Agent A2A 与 AG-UI 统一实施目标

本期范围限于 H Agent 个人工作区。用户通过现有聊天、Harness 会话和业务页面发起工作、查看进度、补充信息和领取产物。A2A 支持跨服务委派与交付，AG-UI 支持用户与 Agent 围绕同一会话、文档或业务对象协作。

## 1. 远端故事创作、追问与插画交付

**场景**　用户请故事助手写一个太空故事。远端创作 Agent 询问受众和风格。用户刷新页面后补充信息，在聊天中看到初稿逐步出现。途中断线，重新打开会话后可以接着查看进度或读取完整初稿。用户随后请助手为故事配图，图片交付到原会话。

**目标**　远端 Agent 可以通过 `input-required` 发起追问，用户补充后续接同一个 A2A 任务。聊天可实时展示远端产物，连接恢复后从原任务取得已有内容和后续进展。故事初稿与修订稿可辨认。插画 Agent 可从故事文本生成图片文件产物，图片纳入现有 MinIO 和聊天资源权限体系。

## 2. 按技能发现 Agent 与多跳稿件审核

**场景**　用户提交稿件和参考资料，请故事助手评分并审阅。助手发现在线的评分和编辑技能。风格编辑 Agent 进一步委派事实核查 Agent，根据核查结果修订稿件或标注证据不足，用户在原会话收到评分和编辑结果。

**目标**　远端 Agent 可以在同一张 AgentCard 上发布多个技能。故事助手能够通过 Nacos 发现候选 Agent，并按技能、标签、媒体类型和可用能力选择在线服务。新增符合条件的 Agent 或已有 Agent 下线后，后续请求反映当前可用情况。多跳任务关系可追溯，Langfuse 可查看跨服务调用和异常。用户能区分审核成功、证据不足及下游失败。

## 3. 按身份发现和使用私有技能

**场景**　普通用户可以在故事助手中创作和编辑。获授权的用户还能发现并使用长篇小说模式，从原会话查看相应任务和产物。

**目标**　公开 AgentCard 展示基础技能和认证要求，扩展卡片按已认证身份展示获准使用的技能。私有技能调用、任务查询、订阅、续接和取消，以及相关资源访问，均受项目的用户权限约束。

## 4. 远端文档解析、原文复核与协作画布

**场景**　用户在个人聊天上传扫描报告，远端文档 Agent 完成解析和 OCR，结果回到原会话。用户打开画布，定位原文中的模糊表格，选中对应区域重新识别或手动修正。随后用户修改第二段，请 Agent 基于当前稿续写，最后导出确认后的版本。用户也可以从空白画布开始创作。

**目标**　文档 Agent 能通过 A2A 接收 PDF 文件，交付可追溯到原文页码的正文、结构和质量信息。AgentCard 声明各技能支持的输入和输出媒体类型。聊天和画布能够围绕同一份稿件及其待复核项继续工作，Agent 可理解用户选区并定位相应原文。用户和 Agent 的合法修改及时可见，下一轮使用当前版本。并发修改发生冲突时，用户可辨认冲突并恢复自己的编辑。刷新后可找回稿件和待复核项，导出内容与用户确认的版本一致。

## 5. 个人长任务看板与结果回填

**场景**　用户在个人工作区发起视频生成、远端文档解析和自动化试跑，然后关闭页面。回来后，可以看到三项任务的最新状态，打开已交付的产物，处理待确认项，或对支持的任务请求取消和重试。

**目标**　个人任务看板统一呈现文档处理、视频生成和自动化运行的来源、真实状态、可用操作及产物，并可回到发起会话。远端文档任务提交后及时显示受理状态，页面关闭期间仍可向 H Agent 推送结果，推送不可达时仍可查询状态。服务重启后可查询原任务、恢复未完成工作。取消与重试显示实际结果。刷新后恢复原任务，同一次操作或通知的重复到达不会导致重复执行或交付。产物可在有权限的后续对话中引用。

## 6. 工具调用与执行过程

**场景**　用户请个人 Agent 搜索知识库、读取文件并整理引用。Agent 连续发起两次搜索。用户展开执行过程，可分别看到两次查询使用的条件、各自的结果以及需要确认的操作。

**目标**　个人聊天和 Harness 能呈现实际工具调用的开始、可见参数、业务结果、等待和失败状态。增量可用时及时展示，完整参数可用时呈现完整内容。参数与结果归属到对应调用，刷新或回看历史时可恢复已保存记录。远端执行过程按其实际提供且允许公开的信息呈现，实时和历史展示遵守敏感信息权限。

## 7. 订单与工单逐项处理

**场景**　运营人员在页面选中三个订单，让助手检查关联工单。Agent 逐项给出建议和待补信息。用户修改一项备注，只确认其中两项，稍后再处理剩余一项。

**目标**　助手能理解页面上明确选定的订单或工单，定位相关详情并提供逐项方案。用户可以补充信息、修改、确认或拒绝。每项决定对应各自的执行状态和回执。刷新后可以继续处理待确认项，提交内容以用户确认的事项和有效版本为准。

## 8. 个人 Harness 调研与子 Agent 协作

**场景**　用户在个人 Harness 会话发起一项调研，主 Agent 将资料收集、方案比较和验证分配给不同子 Agent。用户可以打开任一分支查看步骤和产物，只重试失败的分支，最后在主会话收到汇总。

**目标**　个人会话可呈现委托关系、各分支的状态、消息、工具步骤、待确认事项和产物。刷新后可回到原分支。支持单独停止或重试相应分支，已完成的其他分支结果仍可用于汇总。用户能够辨认缺失或失败的部分。

## 9. 知识库增量编辑与来源核对

**场景**　用户在个人知识库选中一个条目，补充新资料后请助手更新适用条件。助手给出分段修改草稿，用户打开引用核对原文、调整表述，并只采纳其中两段。

**目标**　助手能围绕用户选中的条目和段落工作，并展示来源、正文差异及待提交草稿。用户可以逐段接受、调整或放弃，提交后的版本与来源可查。草稿期间原条目发生变化时，用户能核对最新版本并找回已编辑的内容。知识库写入遵守现有个人权限。

## 10. 自动化提案编辑与试跑

**场景**　用户请助手每周汇总未结工单。在自动化页面，用户将运行时间改为九点并确认时区，先试跑一次查看真实结果，再决定是否启用。

**目标**　聊天和自动化页面共同呈现同一份提案，用户和 Agent 都可查看、修订指令、执行会话及日程。用户修改在后续对话中可用。试跑交付可在任务看板或原会话找到，正式启用以用户最后确认的版本为准。
