# AG-UI 对话与卡片

用户于 2026-10-23 确认实施。

## 已确认范围

- 网页端三类运行时、父子会话、审批续跑统一使用 AG-UI。
- 前端采用 CopilotKit v2，自托管 Runtime 位于现有 Next.js 服务，通过官方 HttpAgent 调用 Java。
- Java 保留现有 Agent、会话、授权、业务 Run、审批和观测。AgentScope 复用官方 2.0.2 事件转换器；LangChain4j 回调和工作流节点做协议适配。
- 对外协议模型、序列化和 SSE 编码采用 AG-UI 官方仓库收录的社区 Java SDK；AgentScope 的协议类型仅在 Harness 适配器内部使用。
- 保留 448px 窄版布局，Inspector 仅在开发环境显式 `debug=1` 时开启；恢复输入框历史参考图选择及原有历史消息排列。
- 默认展示简洁进度，展开查看步骤、工具摘要、输出和协作者状态。
- 持久化关键步骤与业务卡片快照，不建立全量 token/原始事件日志。旧消息继续展示，不补造历史过程。
- 浏览器断线不取消任务。显式停止父任务时停止其未完成后代；停止子任务只影响该分支。停止不撤销已经完成的操作。
- 首张业务卡片采用已有自动化提案，保留确认与放弃的服务端授权和幂等规则。

## 设计约束

- Java 数据库拥有产品会话、业务 Run、审批和卡片状态；CopilotKit Runtime 负责协议路由，不建立另一套业务状态来源。
- SDK threadId 对应实际 Agent Session，runId 对应一次 AG-UI 交互；审批续跑保留业务 Agent Run 身份。
- 项目负责执行与订阅生命周期；对外使用社区 SDK 的事件、序列化和输出组件，Harness 复用 AgentScope 官方转换器，不让 HTTP 连接生命周期拥有业务运行。
- 主回复与子 Agent 内容隔离，事件和卡片使用稳定身份去重。客户端不能通过提交消息历史、用户 ID 或父子路径改变服务端授权和模型上下文。
- 新连接从持久化快照和当前状态恢复；连接本身不重新启动已提交的任务。服务进程故障与浏览器断线分开处理，不能自动重复有副作用的工具。

## 验收

三类 Agent 正常交互，步骤/工具状态可见，审批暂停和继续，自动化提案交互与刷新恢复，父子消息隔离，断线后继续和重新观察，显式停止级联；保留原有资源、会话权限和并发保护。
