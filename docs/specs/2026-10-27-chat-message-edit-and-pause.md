# 聊天消息编辑与暂停续写

## 已确认的行为

- 只允许编辑当前会话最近一条用户消息，即使它后面已有 AI 回复。
- 在原消息处修改文字，保留附件；提供“保存并重新回答”和“取消”。
- 保存到后端并替换该轮旧回复；重新回答失败时保留修改并允许重试。
- 运行中或等待批准时不能编辑；用户可以先暂停或停止。
- 暂停后，输入框为空时显示“继续回答”；输入新文字时切回发送，结束旧回答并创建新消息。
- 继续时保留半截回答，在同一条 AI 消息中续写，不创建可见的合成用户消息。

## 实现边界

消息编辑及续写都通过 AG-UI 的 `forwardedProps.operation` 发起。编辑使用 `messageId` 和 `text`；续写使用 `sourceRunId`。后端解析原消息、附件及半截回答，并在取得会话执行 permit 后再次校验最新用户消息。客户端提交的历史不能覆盖服务器上下文。

被替换的产品消息使用 `superseded_at` 隐藏。保留原行及其外键，以免级联删除业务 Run、资源或生成任务。消息序号保持单调递增。对应的 AG-UI 旧快照同时退役，重连不会恢复旧回复。

执行新回答前重建本会话的模型工作上下文：普通聊天更新 Redis 和数据库快照；Harness 更新持久化 AgentState，并清除本地缓存。编辑后的模型上下文不包含旧问题和旧回复。续写时明确提供原请求、半截回答及已有工具和任务结果，要求复用已提交任务。

暂停为服务器取消当前生成并保存 `PAUSED` 快照；重连只观察状态。继续时发起新的模型调用，合并原半截文字和新输出。无法逐字恢复已经取消的供应商原始流，衔接处可能少量重复。续写失败仍可从其已保存的半截内容重试。

已提交的图片和视频任务独立运行，暂停聊天不会撤销它们。它们仍可能完成并回填，编辑也不回滚已经发生的工具副作用。

## 验证

- 前端交互：最近消息编辑入口、运行时禁用、暂停后空输入框继续、有文字时新发消息。
- 后端运行：所有权与最新用户消息校验、消息身份复用、暂停保存、同一回答目标续写、失败重试。
- PostgreSQL：文字与 payload 同步更新、历史隐藏旧回复、原行保留、序号不复用。
- 前端回归、TypeScript 和构建；后端聊天、AG-UI、Harness、成功提交与持久化回归。

部署时需应用 `V20261027_02__chat_message_revision_and_pause.sql`，再启用新后端与前端。

## 2026-10-28 交互调整

参考 deepseek-harness 的 `MessageIconActions`、`InlineEditor` 和 `InputBar`：

- 编辑按钮与复制按钮共用一排轻量图标，保留文字提示和可访问名称。较早消息在悬停或键盘聚焦时显示操作；触屏始终显示。
- 编辑框自适应高度，使用勾选保存、叉号取消。Enter 保存，Shift+Enter 换行，Esc 取消并恢复焦点；输入法组合输入不触发保存。空文字与未改变的文字不能重发。
- 输入框只保留一个主按钮，按状态切换暂停、继续或发送图标；颜色、尺寸及位置保持一致。暂停请求处理中禁用按钮并显示等待状态。
- 恢复连接和结束回答收进对话选项，支持点击外部或 Esc 关闭。附件及后端编辑、续写协议保持原有行为。

## 编辑后的思考计时

用户消息 ID 在编辑后保持不变，但重答属于新的思考过程。后端进度通过 `replacesPrevious` 明确标记替换；前端丢弃该消息之前的过程，避免使用旧回答的开始时间与新回答的结束时间计算耗时。无标记的历史已完成过程也作为替换边界。

暂停或批准后的继续执行保留同一过程的阅读状态，耗时累计各次执行的有效区间，排除暂停和等待批准的空档。历史记录缺少结束时间时不以浏览器当前时间补算已结束过程。
