# AG-UI 思考与执行过程

用户于 2026-10-26 确认交互并授权实施。

## 交互

- 每轮回答只有一个轻量过程入口，去掉独立的“Agent 已完成”卡片与重复的思考入口。
- 等待期间默认展开，模型提供的思考文字按增量追加，工具和工作流步骤按发生顺序穿插。工具结果按需展开。
- 首个非空回答内容到达后自动收起。创建空消息或收到工具参数结束事件均不触发收起。
- 收起后显示“思考了 N 秒 · 调用工具 M 次”；没有思考文本时使用“处理了 N 秒”。旧历史缺少时间时不补造时长。
- 回答开始后再次调用工具，只更新入口状态，不自动重新展开。
- 用户一旦手动展开或收起，本轮保持用户选择，后续增量、完成及审批续跑不覆盖选择。
- 失败、中断、停止、拦截和等待审批保留独立状态文案。终止错误原因与原有审批操作直接可见；单个工具失败只标记该步骤，不把整轮误报为失败。
- 历史记录默认收起；同一轮的运行快照、持久化思考及审批续跑合并展示。没有运行快照的旧思考使用同一外观。

## 事件与恢复

- 复用 `h-agent.progress` 活动，以 `ACTIVITY_DELTA` 的 JSON Patch 即时发送思考增量、步骤变化及回答开始标记。
- `entries` 保留思考块和步骤引用的顺序；思考块以 `chunks` 接收增量。快照将同一块的文本压紧，不持久化 token 日志。
- `answerStarted` 由实际正文内容设置并保持为真；`startedAt` / `processEndedAt` 固定开始等待到首次正文或终态的时间范围。
- 定期快照和重连仍使用 `ACTIVITY_SNAPSHOT`，数据库写入节奏不随 token 增加。
- `TOOL_CALL_END` 只表示参数结束，结果状态来自执行结果；Harness 的空结果和失败状态在协议适配边界统一处理。
- 产品消息转换只影响展示，不改写 SDK 消息状态。已经进入统一过程的工具消息不再重复渲染为卡片。

## 验证

- Java 投影测试：即时思考增量、时间顺序、回答开始标记、工具执行失败与参数结束的区别。
- Runtime 测试：重连时运行过程与持久化思考去重，保持旧历史和资源的排列。
- 前端组件测试：默认展开、增量显示、自动收起、后续工具、用户手动开合、历史收起与直接展示错误原因。
- 消息转换测试：历史分页、审批续跑、工具去重、稳定身份，以及资源说明不误触发收起。
