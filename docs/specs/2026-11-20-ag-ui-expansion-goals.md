# H Agent AG-UI 扩展实施目标

在 H Agent 现有个人工作区中，让用户和 Agent 围绕同一份文档、业务对象或后台任务协作。用户可以在页面上选择对象、直接编辑内容、确认或拒绝操作，再通过聊天继续原来的工作。执行状态和产物在原会话或对应业务页面中可查，并能在后续对话中继续引用。

## 范围

覆盖个人聊天、个人 Harness 会话及其协作 Agent、订单处理助手、个人知识库和自动化任务。本期 Team 相关逻辑不在实施范围内，包括 Matrix 房间、Team Manager 与 Worker，以及 Team 任务和产物的归属与交付。以下场景以正常产品入口、真实会话和项目现有业务服务为验收基础。 [现有 AG-UI 对话能力](2026-10-23-ag-ui-chat.md)

## 1. 协作文档画布与原文复核

**场景**　用户在个人聊天上传一份扫描报告。Agent 解析原文，在聊天右侧画布逐段整理内容。遇到识别不清的表格时，Agent 打开原文并定位到对应区域。用户可以人工修正，或说「只重新识别我选中的表格」。复核完成后，用户直接在画布改写第二段，再请 Agent 基于改过的版本补上结论，最后将当前稿导出并交付到会话。

**目标**　一次会话中可从现有文档解析、OCR 和人工复核流程进入同一份可持续编辑的文档，也可从空白稿开始创作。Agent 写入的内容及时出现在画布上，用户修改立即可见，并成为下一轮续写和修订的输入。聊天可以引用当前选区，Agent 可以在页面中定位对应原文。 [文档能力需求](2026-11-04-document-parse-ocr-generation-requirements.md)

**验收**　Agent 写入三段，用户修改第二段后要求续写，新内容基于修订稿，其他段落保持正确。若用户和 Agent 同时修改同一区域，界面能提示冲突并保留用户可恢复的编辑。刷新后可以继续处理同一份文档及待复核项，导出的文件与用户确认的稿件一致。

## 2. 个人长任务实时看板

**场景**　用户在聊天发起视频生成，又提交一份待解析的文档，稍后还触发一次自动化任务。用户离开聊天后，可在个人工作区看到各任务是已受理、执行中、等待确认、失败还是已交付。失败的任务可以重试，支持取消的运行可以请求取消，已交付的结果可以打开或引用到聊天。

**目标**　把个人视频生成、文档处理与自动化运行放在同一任务视图中。卡片随实际业务进度更新，保留任务来源、运行状态、可用操作与最终产物。用户可从看板回到原会话，也可通过个人 Agent 操作明确指定的任务。卡片动作的结果能在后续对话中使用。 [异步媒体生成](../2026-07-14-async-media-generation-ddd-design.md) · [自动化任务](2026-09-09-automation-xxl-job-unification-design.md)

**验收**　三类任务均可从现有入口发起，并在看板显示实际进度。聊天回复结束或浏览器重新连接后，仍能查看同一任务及结果。取消与重试显示业务确认后的实际状态，重复点击不会产生重复任务或交付。产物可在原会话打开，也可在有权限的后续对话中引用。

## 3. 真实工具调用与参数展示

**场景**　用户请 Agent 检索知识库、读取指定文件并整理引用。执行过程中，用户可以展开对应工具步骤，看到实际搜索词、可展示的文件路径或查询条件，随后查看结果、失败原因或需要确认的动作。

**目标**　个人聊天和个人 Harness 的工具过程能展示真实、可公开给当前用户的调用参数。运行时提供参数增量时，界面随实际片段更新。运行时提供完整参数时，界面在参数可用后显示。每次调用的参数、执行结果和业务步骤可对应，历史记录可以恢复已保存的展示内容。 [现有执行过程](2026-10-26-ag-ui-process.md) · [AG-UI 工具调用规范](https://github.com/ag-ui-protocol/ag-ui/blob/main/docs/spec/1.0/events/tool-calls.mdx)

**验收**　同一轮调用两次同名搜索工具时，两组查询条件和结果能正确对应。参数接收完毕后，界面仍按实际执行结果显示完成、等待确认或失败。敏感字段在实时过程和历史中都不暴露。

## 4. 订单与工单的逐项处理

**场景**　运营人员选中三个订单，让助手检查其关联工单。Agent 打开相关详情，并逐单展示建议与待补信息。用户调整一项备注，只确认其中两项，剩余一项继续待处理。

**目标**　订单处理助手能够理解用户在页面上明确选中的订单或工单，展示逐项查询结果和结构化方案。用户可以按业务规则补充信息、修改提案、确认或拒绝，并看到每项决定对应的执行回执。 [订单处理助手](2026-10-23-order-processing-agent-design.md)

**验收**　部分确认只执行选中的事项。刷新后，已处理、失败和待确认项仍各自可辨认。过期方案或重复确认不会误执行，用户可查看最新业务结果并继续处理剩余事项。

## 5. 个人 Harness 调研与子 Agent 协作

**场景**　用户在个人 Harness 会话请 Agent 调研三个技术方向。主 Agent 将资料搜集、对比和验证交给不同协作 Agent。用户可以打开某个分支查看委托、步骤和产物，并只要求失败的分支重试，最终在主会话收到整合结果。

**目标**　用户能追踪个人会话内的委托关系和每个分支的运行状态。分支的回复、工具步骤、待确认项与产物可以单独查看，主会话能够引用各分支结果并呈现最终交付。

**验收**　多个协作 Agent 并行运行时，其进度和结果归属正确。关闭分支面板或刷新后可以继续观察原任务。只停止或重试一个分支时，其他分支的成果仍可用，主会话能说明失败或缺失的部分。

## 6. 知识库增量编辑与来源核对

**场景**　用户在个人知识库选中一条由 Agent 沉淀的条目，附上新资料后说「只更新适用条件」。Agent 给出修改草稿，用户打开引用核对原文，只应用其中两段。

**目标**　知识库助手能够围绕选中的条目和段落工作，展示来源、正文差异与待提交草稿。用户可以逐段接受、调整或放弃，提交后的版本和来源可查。写入继续受个人知识库的现有权限约束。 [用户知识库工具](../superpowers/specs/2026-11-09-user-knowledge-tools.md)

**验收**　选择并提交两段后，仅认可的变更进入新版本，来源仍可追溯。草稿期间若原条目已更新，界面能提示用户按最新版本核对，用户已编辑的内容可恢复。

## 7. 自动化提案编辑与试跑

**场景**　用户说「每周一早上汇总未结工单」。页面同步展示任务指令、执行会话、时区与预定运行时间。用户将时间改为九点，先试跑一次查看真实结果，再确认启用。后续每次运行的进度和交付可从任务看板及关联会话查看。

**目标**　聊天和自动化页面共同呈现同一份提案。Agent 和用户均可修订拟定参数，用户可检查计划、试跑、查看产物，再决定是否启用。 [自动化计划与提案](2026-09-09-automation-xxl-job-unification-design.md)

**验收**　用户改动的时间和时区能在下一轮被 Agent 读到，页面显示的预定触发时间与之对应。试跑产生可追踪的执行结果，启用后实际配置与用户最后确认的版本一致。

## AG-UI 能力覆盖

| 能力 | 在 H Agent 中达到的效果 |
| --- | --- |
| 运行生命周期、步骤和文本流 | 回复及时可见，用户能区分运行中、等待、失败、停止和完成，并看清当前处理阶段。 |
| 共享状态与 JSON Patch | 文档画布、任务看板和自动化提案支持 `STATE_SNAPSHOT` 恢复整体视图，支持 `STATE_DELTA` 更新变更部分。文档和提案的用户编辑采用乐观更新并即时显示，下一轮通过 `RunAgentInput.state` 基于用户当前版本继续。 |
| 消息与活动快照、活动增量 | 重开会话可恢复消息、进度、审批、订单方案及产物卡。卡片在原位置更新，已有记录和进行中的状态正确衔接。 |
| 工具生命周期、参数与结果 | 一次工具调用的开始、实际参数、参数结束和业务结果均可关联。支持实际参数增量和可展开的结果。 |
| 页面上下文与前端工具 | Agent 理解用户明确选择的页码、段落、订单或任务。可执行定位原文、打开引用和选中产物等页面动作，并接收执行结果。 |
| 人工介入、中断与恢复 | 运行在等待补充、审核或批准时有明确状态。用户可以确认、编辑、拒绝或取消，并沿原业务对象继续。标准中断与恢复覆盖需要 Agent 等待人工输入的场景。 |
| 推理与执行过程 | 对用户提供可展示的处理摘要和真实步骤，按发生顺序呈现，工具或分支异常可单独辨认。 |
| 子 Agent 归属与生命周期 | 在个人 Harness 会话中追踪各分支的开始、结束、错误及其消息、步骤和产物。 |
| 自定义及透传事件 | 遇到标准事件未覆盖的业务扩展时，可呈现来源和含义明确的项目事件，例如产物投递回执。未识别的扩展事件不影响标准会话和任务状态的呈现。 |

## 整体验收

- 七个场景都能通过 H Agent 的个人工作区正常入口操作，使用可持久化的真实会话、任务、业务状态和产物完成端到端验收。
- 已保存的草稿、等待事项、后台任务和已交付产物在刷新、断线重连或重新登录后仍可找回。恢复页面不会重复提交任务或重复执行业务操作。
- 聊天、画布、卡片和业务页面显示的结果与项目记录一致。并发修改、部分失败、取消和重试都有可辨认的结果。
- 会话、任务、业务对象及资源继续遵守现有授权边界。个人工作区的变更通过现有 Team 行为回归验证。
