# 聊天滚动位置与拓扑卡片吸顶设计

## 目标

领域智能体聊天页需要满足两个滚动行为：向下阅读时，“拓扑详情”卡片固定在聊天区域顶部；向上加载更早消息成功后，用户仍停留在加载前正在阅读的消息附近，而不是跳到最新一条。

## 根因

聊天页面当前使用 `min-h-screen`，消息区域作为 flex 子项会被全部消息内容撑高，实际滚动者是 `document`，而不是 `historyContainerRef` 指向的消息区域。加载旧消息后，代码一方面对这个未形成滚动上下文的元素调用固定 `top: 40`，另一方面监听所有 `messages` 变化并滚动到底部；prepend 历史消息因此被当作新回复，最终跳到最新消息。

## 设计

1. 将聊天主体约束为 `h-dvh overflow-hidden`，并给消息区域增加 `min-h-0`，使 `historyContainerRef` 成为唯一的纵向聊天滚动容器。
2. 仅在领域智能体模式下，把 Domain Agent 卡片放入消息容器内的 `sticky top-0` 包装层。包装层使用页面同色半透明背景和较高层级，滚动内容不会透过卡片干扰阅读。
3. 分页请求成功、prepend 消息之前，记录消息容器的 `scrollHeight` 与 `scrollTop`。React 提交新消息后，在 layout effect 中设置：`nextScrollTop = previousScrollTop + nextScrollHeight - previousScrollHeight`。这样新增内容把原消息向下推多少，视口就同步向下补偿多少。
4. 同一个 layout effect 区分“历史 prepend”和普通消息更新。存在待恢复锚点时只恢复位置并跳过末尾滚动；首次载入、用户发送和流式回复仍沿用当前滚到底部行为。

## 边界与错误处理

- 历史请求失败时不写入待恢复锚点，保持原位置并显示现有错误信息。
- 容器不存在时滚动计算不执行，不影响消息数据更新。
- `nextScrollHeight` 小于旧高度时将结果限制为非负数。
- 本次不改分页接口、消息顺序、侧栏历史会话或输入框定位。

## 验证

- 纯函数测试覆盖新增高度补偿、原有 scrollTop 保留和非负下限。
- 运行前端完整 Node 测试与 ESLint。
- 在已登录的本地页面验证：document 不再承担聊天滚动；拓扑卡片吸顶；加载旧消息前后的可见消息保持一致；发送消息仍滚到最新回复。
