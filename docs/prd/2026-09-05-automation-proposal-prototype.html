自动化任务（定时 Agent）— 产品原型 v3

默认关闭 · 每用户最多开启 3 个 · 提案-确认 · 隔离运行 · 幂等调度与独立投递

三个用户场景（Agent 写操作一律走「提案-确认」）

Agent 从不直接改任务：它只生成提案，本轮自然结束；用户点卡片按钮后由前端直调 REST。管理页是用户直接操作，但仍执行相同的版本、名额和权限校验。

改任务「日报改成每周一发」→ 变更提案卡片 → 点确认生效

提案生命周期：生成后 24 小时内未确认自动过期；确认时重新校验所有权和任务版本。重复点击返回首次结果，过期或基线版本已变化时要求重新生成提案。

通用自动化语义：聊天内写操作先确认；创建默认关闭；开启有名额限制；调度器至少一次触发、平台数据库至多一次接纳；每次 Run 隔离执行；结果投递与 Run 分离。“无投递”只代表不发送结果，不授权 Agent 绕过平台策略自行外发。
现状 → 演进：现有代码已具备双框架直接创建、REST 管理页和轮询协调器。本版要求写工具改为只提案，创建默认关闭；执行侧保留 adapter，但在前面增加版本化接纳模块，并把每次运行迁移到独立 run session。

提案、开启与可靠运行时序

确认创建只保存关闭任务；用户明确开启并占用名额后，本地 outbox 异步同步 XXL-Job。外部触发先防重接纳，再进入隔离 Run。

投递与主流程解耦

Agent Run 与产物投递是两条独立链路：Run 只负责产出 Artifact，投递意图先落库（PENDING），投递器独立消费分发。创建任务时声明投递目的。

手动创建表单（点上方「＋ 新建任务」体验）

形态对齐 TraeWork / OpenClaw：任务内容就是一个自然语言 prompt 大文本框，不是 Skill 选择器。prompt 里可以自然引用 Skill（Agent 执行时按需加载）。

任务内容：聊天描述与手动表单最终形成同一个 instruction，但执行时还会冻结任务版本、运行策略、权限范围、上下文截止时间和投递目标。自然语言不能扩大工具权限或替代结构化投递配置。
