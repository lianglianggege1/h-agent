自动化任务（定时 Agent）— 产品原型 v2

提案-确认机制（无 HITL 暂停）· 聊天 CRUD + 管理页面 · 双框架执行 · XXL-Job 调度 · 对齐 OpenClaw Automations

三个用户场景（写操作一律走「提案-确认」）

Agent 从不直接改任务：它只生成提案，本轮自然结束；用户点卡片按钮，前端直调 REST 生效。

用户聊天自然语言发起
提案-确认Agent 提案 · 轮次外 REST 确认

到点执行双框架路由 Agent Run
结果投递卡片回原会话 + Trace
与 OpenClaw 的对齐与差异：对齐——聊天内 automations 工具 CRUD、结果投递、运行历史与 Trace、隔离运行。差异（更保守）——写操作增加提案-确认门槛，OpenClaw 为直接执行。投递层对齐其 channel/webhook/nowhere 三态：我们会话卡片（默认）+ 邮箱（V1.5）+ 无（Agent 自行投递），webhook 列入 V2。机制上不依赖任何引擎的暂停/恢复能力，LangChain4j 与 AgentScope 完全同构。
现状 → 演进：现有代码已具备双框架 create_automation_task 工具（直接创建）、REST 管理接口与管理页。本版演进为：写操作改走提案（新增提案表 + confirm/cancel 端点 + 会话注入消息），读操作不变；执行侧复用现有 AutomationRunCoordinator 派发链路。

提案-确认机制时序

三个阶段：轮次内 Agent 只提案；轮次外前端直调 REST 确认；到点后独立执行并投递。全程无 Run 暂停。

投递与主流程解耦

Agent Run 与产物投递是两条独立链路：Run 只负责产出 Artifact，投递意图先落库（PENDING），投递器独立消费分发。创建任务时声明投递目的。

手动创建表单（点上方「＋ 新建任务」体验）

形态对齐 TraeWork / OpenClaw：任务内容就是一个自然语言 prompt 大文本框，不是 Skill 选择器。prompt 里可以自然引用 Skill（Agent 执行时按需加载）。

任务内容的两种写法（同一字段）：① 聊天中描述——用户说「每天早 9 点总结昨天会话」，Agent 解析成五要素提案；② 手动创建描述——用户直接在下框里写 prompt，如「用周报 Skill 整理我昨天全部会话，输出 5 条要点」。两者最终存的是同一个自然语言 prompt 字符串，执行时由目标 Agent（h-agent / harness-agent）作为一次用户消息注入运行。
