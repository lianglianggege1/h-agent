自动化任务（定时 Agent）— 产品原型

聊天内 CRUD + 管理页面 · 双框架执行（h-agent / harness-agent）· XXL-Job 调度 · 对齐 OpenClaw Automations

三个用户场景

用户的全部操作都发生在聊天和「我的」里，不感知 XXL-Job、cron 表达式等系统细节。

A创建任务（自然语言 → 确认卡片）
说需求「每天早上 9 点总结我昨天的会话，发到这个聊天里」
Agent 出确认卡片解析出名称 / 调度 / 执行 Agent / 任务内容，让用户确认
用户点「确认创建」可选：先修改参数再确认；不改则跳过
创建成功回复任务卡片：下次运行时间 + 入口「在管理页查看」
B到点执行 → 结果投递回聊天
到点触发无需用户在线；系统时间线出现在聊天流中
Agent 独立运行按任务内容执行一次完整 Agent Run（可带工具、记忆）
结果卡片投递输出摘要卡片进入原会话，可展开查看全文
用户继续对话直接在卡片下方追问，Agent 带上下文接续
C日常管理（聊天 或 管理页，两条路等价）
问任务「我有哪些定时任务？」→ 列表卡片
改任务「日报改成每周一发」→ 变更确认卡片 → 确认
暂停 / 恢复「先暂停日报」/「恢复日报」
删除「删掉日报任务」→ 二次确认（危险操作）
等价性原则：聊天中 Agent 能做的任务操作，管理页面全部提供；管理页面的操作也会在聊天里留下轻量记录。两个入口操作同一份任务数据，无主副本之分。

端到端系统链路

用户一次「创建 → 执行 → 投递」在系统中的完整路径。

▸ 橙色节点：用户直接交互的关键界面（确认卡片） ▸ 蓝色节点：双框架路由（本需求第 1 条） ▸ XXL-Job 只负责「到点触发」，任务语义（归属/历史/投递）全在自己库里
与 OpenClaw 的对齐点：① 自然语言创建 + 确认卡片（≈ automations 工具 + /loop）；② 结果投递回原会话（≈ --session main + announce）；③ 任务 CRUD 聊天与页面双入口；④ 运行历史与 Trace 关联。

设计要点：① 创建 / 变更 / 删除一律出确认卡片，用户点了才生效（对齐现有 HITL 审批交互）；② 失败运行也投递卡片，用户不需要去管理页才知道任务挂了；③ 执行者可以是通用助手、领域 Agent 或 harness-agent，由任务创建时所在会话决定，也可在确认卡片里改。
